# seminar-report-v1 디자인 규칙

이 템플릿은 `study` 저장소의 `study-report-v1` 을 세미나용으로 파생한 HTML 리포트다.
`study-report-v1` 자체가 발표자의 자체 출판 템플릿 `ai-odyssey-publisher` 의 `theme_report.css`
와 `report.js` 를 이식한 것이므로, 이 템플릿은 그 계보를 두 단계 물려받는다. CSS 셀렉터가
정본을 완전히 포함하는 상위집합이라 컴포넌트 이름이 그대로 통한다. A4 인쇄 규칙, continuous-mode,
섹션 계층, 표·그림 캡션, callout, 목차 드로어, 설정 패널, 다크 테마, 이미지 뷰어를 그대로 쓴다.

- 완성 기준 예시: `html/seminars/computer-use/report.html`
- 공통 설계 청사진: `agent-support/templates/SEMINAR_SESSION_BLUEPRINT.md`

## 스터디와 다른 점

| study-report-v1 | seminar-report-v1 |
|---|---|
| 교재의 장·절 순서와 번호·번역 제목을 그대로 사용한 본문 | 발표자가 구성한 섹션이 정본. 보존할 원본 목차가 없다 |
| `data-source-kind="section"` · `data-source-ref="3.1"` | `data-source-kind="vendor\|spec\|measured"` · `data-source-ref="<슬러그>"` |
| `AIML Quant Supplements` 로 원본 범위 밖 내용 구분 | 구분하지 않는다. 전부 발표자 저작이다 |
| `materials_path` 의 비공개 교재 | 공개 1차 자료. 링크로 직접 참조한다 |
| 6\~10개 도형/표 | 섹션당 최소 1개, 전체 12\~25개 |

`.report-section` 자동 목차, 그림·표 캡션 계약, `data-deck-use="required"`, 이미지 라이트박스는
**바뀌지 않는다.**

## 금지

- 템플릿을 별도 카드형 CSS로 다시 작성하는 것
- 슬라이드 CSS를 리포트에 재사용하는 것
- 리포트를 슬라이드 문장 확장본으로 만드는 것
- 사내 색 토큰 `#A50034` · `#6E0022` 을 남기는 것

## 필수 산출물

한 세미나는 기본적으로 다음을 함께 제공한다.

1. `report.html` — 발표에서 생략한 정의·근거·논리·사례·판단 기준을 보존하는 상세 자료.
2. `index.html` — 발표용 슬라이드이자 공유 URL.
3. `assets/figs/*.svg` — 발표자가 재구성한 도해.
4. `seminar.toml` — 세미나 메타데이터와 report 경로.

상세 리포트가 없는 슬라이드 단독 산출물은 완료로 간주하지 않는다.

## 표준 정보 구조

1. `.report-cover` — 워드마크, 시리즈, 제목, 부제, 발표자·범위·일시.
2. Section 00 · Summary — 한 문장 결론, 핵심 질문, 전체 논리표.
3. 본문 섹션 — 발표자가 구성한 순서. 각 섹션에 안정적인 `id`.
4. `.report-appendix` — 용어, 참고문헌, 그림 출처.

`정의 → 지형 → 실증 → 위험 → 판단` 은 각 섹션의 설명 누락을 찾는 체크리스트로만 쓴다. 자동
목차는 각 `.report-section` 의 직접 자식 `h1` 과 본문 `h3` 에서 생성되므로 제목 계층을 유지한다.

본문 섹션마다 가능하면 다음 순서를 사용한다.

- `.report-section__kicker` 와 `h1`
- `.section-summary` 로 2\~4개 핵심 요약
- 2개 이상의 설명 단락
- 표 또는 도형
- 필요할 때 `.callout--insight` 또는 `.callout--hero`

## 출처 계약

세미나의 근거는 교재가 아니라 1차 자료다. 다음을 지킨다.

- 벤더 문서·표준 문서·블로그·논문은 **확인일** 과 함께 인용한다. 벤더 제품은 자주 바뀌므로
  확인일 없는 인용은 근거가 아니다.
- 직접 측정한 결과는 `data-source-kind="measured"` 와 재현 조건(모델·버전·환경·일자)을 남긴다.
- 참고문헌은 `.report-appendix` 에 번호를 붙여 모으고, 본문에서 `ref:<번호>` 로 가리킨다.
- LLM이 생성한 문장, 발표자의 추론, 검증된 사실을 문장과 도형에서 구분한다.

## 시각 체계

- 배경 `#FAFAF9`, 본문 `#0F0F10`, 액센트 Deep Navy `#0F2C59` 한 색을 중심으로 쓴다.
- 본문은 continuous mode에서 약 760px 너비로 유지하고 한글 행간을 넉넉히 둔다.
- 화면에서는 양쪽 플로팅 컨트롤, 자동 숨김, 드로어 목차를 사용한다.
- 인쇄에서는 컨트롤을 숨기고 A4 페이지 분리, 표·그림의 `break-inside: avoid` 를 유지한다.
- 외부 CDN, 외부 폰트, 프레임워크에 의존하지 않는다.

## 표와 그림

### 표

모든 표는 `table.cmp-table` 과 아래 캡션 구조를 사용한다.

~~~html
<caption class="cmp-table__caption asset-caption asset-caption--table">
  <div class="asset-caption__inner">
    <span class="asset-caption__chip">표 1</span>
    <span class="asset-caption__title">표 N · 제목</span>
  </div>
</caption>
~~~

표는 정의·비교·역할 분담·판단 질문처럼 반복되는 필드를 정리할 때만 쓴다. 한 칸 안에 긴 에세이를
넣지 않는다. 발표자료가 추적할 수 있도록 핵심 표에는 `id="table-..."` 형식의 고유 ID를 둔다.

**벤더 비교표에는 확인일 열 또는 캡션 확인일이 반드시 있어야 한다.**

### 그림

모든 도형은 `figure.report-figure` 와 그림 번호·제목·근거 메모를 포함한다.

~~~html
<figure class="report-figure" id="fig-example" data-deck-use="required">
  <figcaption class="asset-caption asset-caption--figure">
    <span class="asset-caption__chip">그림 1</span>
    <span class="asset-caption__title">그림 N · 관계가 드러나는 제목</span>
  </figcaption>
  <img src="assets/figs/example.svg" alt="도형이 전달하는 관계를 설명">
  <small class="asset-note">재구성 범위와 출처·확인일.</small>
</figure>
~~~

SVG는 차트·관계도·플로우·타임라인에만 사용한다. 사람·장식 아이콘·일러스트를 그리지 않는다.
외부 SVG의 기본 한글 font stack은 `report.css` 의 `--font-sans-ko` 와 같은 순서로 직접 선언한다.

### 그림 안에 두는 텍스트

**그림을 해독하는 텍스트인가, 설명하는 텍스트인가** 로 가른다. 해독 텍스트는 남긴다 — 그림을
슬라이드로 가져다 쓸 때도 필요하다.

| 남긴다 (해독) | 뺀다 (서술) |
|---|---|
| 축 라벨 · 틱 라벨 | 제목 · 부제 |
| 차트 범례 | 하단 해설문 |
| 노드 정체성 라벨 | 차트 위에 얹은 요약·결과 박스 |
| 데이터 점 · 사건 라벨 | 우측 설명 패널 |
| 다이어그램 셀 안의 수치 | 결론, `라벨 — 설명` 의 설명 꼬리 |

**눈으로 훑으면 넘어가는 다섯 형태:**

1. 제목처럼 보이지 않는 **본문 크기 한 줄 제목**
2. 가장자리가 아니라 **다이어그램 중앙에 놓인 콜아웃**
3. 계열 라벨의 `— 설명` 꼬리
4. 플롯 영역 위에 **떠 있는 결과 박스** (연결선이 닿지 않는다)
5. 다이어그램 우측에 붙은 **설명 패널**

빼기 전에 **figure 블록이 아니라 주변 절 전체를 검색한다.** 잘 쓴 리포트는 이미 그 내용을 본문에
담고 있으므로 기본 동작은 '옮기기'가 아니라 **'삭제'** 다.

이 규칙은 권고가 아니라 게이트다. `validate-site.py` 가 도형 밖 텍스트와 같은 x 로 쌓인 묶음을
28자 미만으로 제한한다.

같은 의미 수준의 박스는 폭·행·열·간격을 공통 그리드에 맞춘다. 화살표는 눈에 보이는 shaft를
확보하고 의도한 도형 면의 중앙 경계에 끝이 닿게 한다. 한 그림에서 결함을 찾으면 모든 형제
그림에서 같은 유형을 다시 검사한다. 좌표만 보지 말고 실제 최종 표시 크기의 렌더를 확인한다.

모든 `.report-section`, 핵심 표와 그림에는 안정적인 `id` 를 둔다. 발표자료가 반드시 재사용해야 할
그림은 `data-deck-use="required"` 로 표시한다. 이 표식은 장식 우선순위가 아니라 주장 전달에
필요한 시각 근거라는 계약이다.

화면에서 `.report-figure` 의 이미지와 SVG는 자동으로 확대 가능한 버튼이 된다. 이 동작을 유지하기
위해 `assets/report.js` 의 `setupImageLightbox()` 와 관련 CSS를 제거하거나 이미지 위에 링크를
씌우지 않는다.

## 품질 기준

- 리포트가 슬라이드 문장 확장본이 아니라 독립적으로 읽히는 상세 자료다.
- 각 핵심 주장에는 정의, 작동 방식, 한계 또는 판단 기준 중 최소 두 가지가 따른다.
- 벤더·제품·가격·한도 정보에 확인일이 있다.
- 데모·측정 결과에 재현 조건이 있고, 실행하지 않은 결과를 적지 않는다.
- 섹션당 최소 하나의 시각적 근거를 두고, 전체 12\~25개의 의미 있는 도형/표를 제공한다.
- 그림과 표 번호는 각 종류별로 1부터 중복·누락 없이 증가한다.
- LLM 생성 결과, 추론 결과, 검증된 사실을 문장과 도형에서 구분한다.
- 사내 색 토큰 `#A50034` · `#6E0022` 가 0건이다.
- 데스크톱 1440px, 390px 모바일, A4/PDF에서 겹침·잘림·과도한 빈 페이지가 없다.
- 목차, 테마, Print/PDF, Report/Slides/Index 링크와 이미지 확대·줌·닫기가 실제로 동작한다.
- **리포트 게이트를 통과하기 전에는 발표자료 본문 작성을 시작하지 않는다.** 발표자료에서 새
  근거가 필요하면 리포트를 먼저 보완한다.

## 자족성 규칙

세미나 폴더의 상대 경로만으로 리포트와 슬라이드가 동작해야 한다. 세미나 파일에서 저장소 밖이나
루트의 임시 파일을 직접 참조하지 않는다. 필요한 도형과 정적 자산은 반드시 세미나 `assets/` 아래에
복사하거나 새로 작성한다.
