# 세미나 산출물 청사진

이 문서는 에이전트가 같은 품질 기준으로 한 세미나의 상세 리포트, 발표 슬라이드와 자동 목차를
만드는 공통 설계도다. `study` 저장소의 `STUDY_SESSION_BLUEPRINT.md` 에서 파생했고, 교재 전제를
1차 자료 전제로 바꾼 것 외에는 같은 계약을 따른다.

## 세미나와 스터디의 경계

| | 스터디 | 세미나 |
|---|---|---|
| 원자료 | 비공개 교재 (`study-materials`) | 공개 1차 자료 — 벤더 공식 문서·표준·논문·직접 측정 |
| 구조 | 교재의 장·절 순서를 보존 | 발표자가 구성한 섹션이 정본 |
| 주기 | 매주 회차가 이어짐 | 1회 완결 또는 파트 분할 |
| 분량 | 50분 18\~30장 | 60분 40\~50장 |
| 저장소 | `study` + `study-materials` | `seminar` 하나. 별도 자료 저장소 없음 |

세미나에 `seminar-materials` 비공개 저장소는 **만들지 않는다.** 원자료가 공개 웹이라 저작권
분리의 이유가 없다. 발표자가 만든 리포트·슬라이드·도해가 곧 자료이고 이 저장소에 공개된다.

## 기준 예시

- 상세 리포트: `html/seminars/computer-use/report.html`
- 발표자료: `html/seminars/computer-use/index.html`
- 메타데이터: `html/seminars/computer-use/seminar.toml`

기준 예시에서 재사용할 것은 색이나 문구가 아니라 다음 완성 조건이다.

- 리포트와 슬라이드가 서로 다른 읽기 목적을 가진 한 쌍이다.
- 1차 자료를 먼저 상세 리포트로 재구성하고, 검증을 마친 리포트를 유일한 발표자료 내용 원천으로
  사용한다.
- 전체 논리가 정의, 지형, 실증, 위험, 판단으로 이어진다.
- 반복되는 비교는 표로, 관계와 순서는 새로 구성한 SVG·HTML 도형으로 설명한다.
- 각 시각자료에 번호, 제목, 대체 텍스트, 재구성 범위와 출처·확인일이 있다.
- 리포트와 슬라이드의 목차는 제목·`aria-label` 에서 자동 생성된다.
- 모든 슬라이드가 근거 리포트 섹션·표·그림을 추적할 수 있다.
- 브라우저, 모바일, 키보드, 인쇄/PDF에서 실제로 사용할 수 있다.

## 한 세미나의 파일 계약

```text
html/seminars/<seminar-slug>/
├── seminar.toml
├── report.html                 # 사후 학습용 상세 리포트
├── index.html                  # 발표용 슬라이드이자 공유 URL
└── assets/
    ├── figs/                   # 세미나에 귀속되는 재구성 SVG·이미지
    ├── report.css
    ├── report.js
    ├── deck.css
    ├── deck.js
    └── deck-lightbox.js
```

새 세미나는 반드시 `agent-support/scripts/new-seminar.py` 로 만든다. 생성된 CSS와 JavaScript는
그 세미나의 스냅샷이다. 공용 템플릿을 개선해도 과거 세미나에 자동 덮어쓰지 않는다.

`<seminar-slug>` 는 곧 공개 URL이고 **한 번 정하면 바꾸지 않는다.** YouTube 설명란이 이 주소를
가리키기 때문이다.

## 하나의 논리, 세 가지 표현

| 논리 역할 | 상세 리포트 | 발표 슬라이드 | 자동 목차의 이름 |
|---|---|---|---|
| 핵심 결론 | Section 00의 한 문장 결론·전체 논리표 | 훅, 오늘의 여정 | `훅`, `오늘의 여정` |
| 정의와 경계 | 정의, 범위, 구성요소, 왜 지금인가 | 섹션 구분 + 개념도 + 전환 배경 | `정의 섹션` 등 |
| 지형 | 대안·벤더·구현체 비교와 선택 기준 | 비교표 + 각 대안의 강점/한계 | `지형 섹션` 등 |
| 실증 | 실제 실행, 관측 결과, 재현 조건 | 데모 요약 + 관측 수치 | `실증 섹션` 등 |
| 위험 | 실패 양상, 보안·거버넌스, 통제 수단 | 실패 유형 + 통제 카드 | `위험과 통제` |
| 판단 | 적합/비적합 신호, 작은 실험, 중단 기준 | 판단표 + 대안 비교 | `도입 판단 기준` |
| 정리 | 용어, 참고문헌, 토론 질문 | 확인 질문 + 세 문장 요약 | `확인 질문`, `정리와 질의응답` |

목차를 별도 파일로 중복 관리하지 않는다. 리포트는 `.report-section` 의 직접 자식 제목과 `h3`,
슬라이드는 각 `.slide` 의 `aria-label` 에서 JavaScript가 목차를 만든다. 목차가 어색하면
JavaScript를 고치기 전에 제목 구조와 `aria-label` 을 고친다.

## 에이전트 작업 순서

### 1. 사실과 범위를 고정한다

1. `agent-support/seminars.toml` 에서 `slug`, 시리즈, 상태를 확인한다.
2. 1차 자료 목록을 만든다 — 벤더 공식 문서 URL, 표준 문서, 논문, 직접 측정 기록.
3. 각 자료의 **확인일** 을 기록한다. 벤더 문서는 개정되므로 확인일 없는 인용을 만들지 않는다.
4. 인용 가능한 원문, 발표자의 해설, 외부 검증 사실을 구분한다.
5. 원자료가 사내 트랙에서 왔다면 **사내 색·조직명·내부 식별자를 먼저 전수 제거** 한다.

### 2. 상세 리포트를 먼저 설계하고 완성한다

작성 전에 아래를 짧게 정한다.

- 발표 전체를 관통하는 질문 1개
- 발표 후 남길 결론 1개
- 본문 섹션 구성과 순서
- 각 섹션을 대표할 표 또는 도형
- 발표에서 반드시 다룰 핵심 관계와 필수 시각자료
- 토론 질문 1\~3개
- 확인이 필요한 외부 주장과 출처

이 단계에서는 슬라이드 본문을 쓰지 않는다. 핵심 표와 그림에 안정적인 `id`, `data-source-kind`,
`data-source-ref` 를 붙인다. 발표에 반드시 사용할 그림에는 `data-deck-use="required"` 를 둔다.

다음 조건을 모두 만족해야 **리포트 게이트** 를 통과한다.

- 핵심 논리와 실패 경계가 빈틈없이 설명된다.
- 표·그림에 번호, 제목, 대체 텍스트, 재구성 범위와 출처·확인일이 있다.
- 자동 목차와 전체화면 이미지 줌·팬·Esc 닫기가 동작한다.
- 1440px, 390px와 실제 A4 PDF에서 내용이 잘리지 않는다.
- 슬라이드에서 쓸 주장과 시각자료가 모두 리포트 안에 존재한다.
- 사내 색 토큰이 0건이다.

### 3. 시각자료를 리포트의 근거로 만든다

- 구조·관계·순서는 SVG 또는 HTML 도형으로 새로 구성한다.
- 반복 필드는 표로 비교한다.
- 장식만 하는 이미지와 의미 없는 KPI 카드는 만들지 않는다.
- 외부 수치와 이미지는 가까운 위치에 직접 출처와 확인일을 표시한다.
- 그림 안에는 해독 텍스트만 남기고 서술 텍스트는 캡션·본문으로 옮기거나 삭제한다.
- 인라인 SVG를 옮겨올 때는 `assets/figs/<이름>.svg` 파일로 분리한다.

### 4. 검증된 리포트에서 슬라이드를 파생한다

리포트 게이트를 통과한 뒤에만 40\~50장의 발표 흐름으로 압축한다. 발표자료에는 리포트에 없는 새
주장·수치·사례를 넣지 않는다. 필요하면 리포트를 먼저 고친 뒤 다시 파생한다.

추적 계약은 다음과 같다.

- `seminar.toml`: `workflow = "source-report-deck-v1"`, `report_source = "report.html"`
- 덱 `<main>`: `data-report-source="report.html"`
- 모든 `.slide`: 실제 리포트 ID를 공백으로 나열한 `data-report-refs`
- 리포트의 모든 `.report-section` 과 `data-deck-use="required"` 그림: 한 번 이상 슬라이드에서
  참조하고, 필수 그림의 같은 `src` 가 덱에 실제로 존재
- 발표 화면의 Report 링크: 가능하면 `report.html#<id>` 로 정확한 근거 위치에 연결

슬라이드는 다음 밀도를 지킨다.

- 결론형 제목 1개
- 왜 중요한지 설명하는 lead 1개
- 한 가지 관계·비교·흐름
- 청중이 기억할 takeaway 1개
- 필요한 경우에만 근접 출처 1개

### 5. 실제 화면으로 검증한다

최소 확인 화면은 다음과 같다.

- 리포트: 1440px 데스크톱, 390px 모바일, A4 PDF
- 슬라이드: 1280×720, 1366×768, 390px 모바일
- 키보드: 리포트 목차와 이미지 뷰어, 슬라이드 이전/다음·Home/End·목차·Esc
- 링크: Index / Report / Slides
- 오프라인: 저장소 루트의 로컬 HTTP 서버에서 외부 CDN 없이 동작

검증 명령:

```bash
python3 -m unittest discover -s agent-support/tests -v
python3 agent-support/scripts/build_site.py
python3 agent-support/scripts/build_site.py --check
python3 agent-support/scripts/validate-site.py --site html
```

### 6. 공개하고 영상과 연결한다

1. `seminars.toml` 에 세미나를 등록하고 `build_site.py` 로 목록을 갱신한다.
2. Pages 배포 뒤 공개 URL이 실제로 열리는지 확인한다.
3. 영상이 **실제 `public`** 이 된 뒤에만 `seminar.toml` 의 `youtube_video_id` 를 기록한다.
4. `media` 저장소에서 해당 영상 설명란이 이 세미나 페이지를 가리키게 갱신한다.

## 완료 체크리스트

- [ ] `report.html`, `index.html`, `seminar.toml`, 로컬 자산이 모두 있다.
- [ ] 리포트가 슬라이드 문장 확장본이 아니라 독립적인 상세 자료다.
- [ ] 1차 자료 감사 뒤 리포트 게이트를 통과하고 나서 발표자료를 만들었다.
- [ ] 모든 벤더·제품·수치 인용에 확인일이 있다.
- [ ] 데모·측정 결과에 재현 조건이 있고 꾸며 낸 결과가 없다.
- [ ] 표·그림에 번호, 제목, 대체 텍스트, 출처 또는 재구성 메모가 있다.
- [ ] 리포트 목차와 슬라이드 목차가 자동으로 생성되고 실제 내용 순서와 맞는다.
- [ ] 모든 슬라이드가 유효한 `data-report-refs` 를 가지며 모든 리포트 섹션과 필수 그림이
      발표자료에서 다뤄진다.
- [ ] 외부 SVG와 리포트 CSS가 같은 기본 한글 font stack을 사용한다.
- [ ] 한 그림의 정렬·화살표 결함을 고친 뒤 모든 형제 그림에서 같은 유형을 다시 확인했다.
- [ ] 이미지 전체화면·줌·팬·Esc 닫기와 포커스 복귀가 동작한다.
- [ ] 슬라이드가 16:9에서 잘리지 않고 키보드·전체화면·테마가 동작한다.
- [ ] A4 PDF에 과도한 빈 페이지, 잘린 표·도형, 중복 번호가 없다.
- [ ] 사내 색 토큰 `#A50034` · `#6E0022` 가 0건이다.
- [ ] 외부 CDN·외부 폰트 참조가 0건이다.
- [ ] 빌드 인덱스와 사이트 검증이 통과한다.

## 참가자가 에이전트에게 요청하는 가장 짧은 문장

```text
<세미나 주제> 세미나 자료를 만들어줘. SEMINAR_SESSION_BLUEPRINT.md 와 두 DESIGN.md 를 따라
1차 자료를 먼저 상세 리포트로 완성·검증하고, 그 리포트의 내용·표·SVG를 반영한 HTML 슬라이드와
자동 목차를 만든 뒤 실제 브라우저와 PDF까지 검증해줘.
```
